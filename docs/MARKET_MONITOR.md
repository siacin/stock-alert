# 情绪周期与板块轮动（盘中观察版）

在网页顶部选择 **情绪与轮动**，点击 **启动市场监控**。它独立于自选股监控：暂停其中一个不会暂停另一个。仅看一轮数据可点“刷新快照”；GET 状态请求本身不会触发外部采集。

不需要 API 密钥，不连接券商、不下单，也不调用收费大模型。电脑保持开机、联网、后台运行，关闭浏览器后仍然采集并记录。手机通过原有私有连接查看相同快照、提醒和设置；锁屏/浏览器后台不保证弹窗。重新启动软件后连续监控默认停止，需手动开启。

## 看什么

- **情绪温度**：涨跌家数、市场广度、中位数、等权平均、大涨/大跌家数和累计成交额。
- **周期观察标签**：温度水平与所选窗口变化组合为低位修复、升温、高位分歧、退潮、低迷、亢奋或震荡，不假设必然按固定顺序演进。
- **日内轨迹**：仅保存交易时段质量合格、时间戳前进的快照。不跨午休、隔夜或长时间断线补画连续曲线。
- **行业轮动**：31 个一级行业的涨跌幅、相对全市场强度、上涨占比、5/15/30 分钟排名变化、成交额占比、领涨股，以及领先/改善/转弱/落后状态。点击热力块可筛选，清空搜索框恢复全部行业。
- **辅助股池**：涨停、跌停、当前触板未封的炸板股池。炸板占比 = 炸板池家数 /（涨停池 + 炸板池家数）。同一只股票多次开板不是多只股票。
- **强度前5板块梯队**：在当日封板/炸板证据之外补入历史价格位置，展示空间板、容量/趋势核心以及首板的低位补涨、高位反包、趋势加速和中位跟随分类。
- **双龙头识别**：板块龙与市场投机龙独立评分，展示候选、分项证据与连续事件响应次数；同一股票可以成为“双重龙头候选”，但两个角色不会互相替代。

### 板块龙与市场投机龙

板块龙回答“谁最能代表并带动这个板块”，评分满分100：板块带动代理25、事件身位20、逻辑关联15、封板质量15、分歧承接10、流动性10、历史记忆5。板块带动代理结合候选首次封板后10分钟内同板块后续封板数，以及连续快照中候选封板/回封或炸板后板块涨停数、炸板率和强度名次的变化。逻辑关联优先采用板块内封板股的细分行业聚类；封单、封板时间和涨停利用率只作为质量证据，不单独决定龙头。

市场投机龙回答“谁是全市场短线资金共同关注的高辨识度载体”，评分满分100：市场空间25、全市场带动代理25、跨平台热度15、分歧生存15、流动性15、独立辨识5。全市场带动代理观察候选封板/回封或炸板后全市场涨停、炸板和情绪温度的后续变化；热度只读取资讯雷达已经取得的同花顺、东方财富、雪球等个股热榜缓存，市场监控不会为评分额外触发资讯抓取。

两个分数都保留每个分项。连续盘中快照少于2次有效事件响应时，无论静态分数多高都只显示“候选”或“空间板待带动验证”；至少2次响应、总分达到70且对应带动分达到55%后才显示“已确认”。被观察股票发生炸板，而板块或市场同时恶化，会计入负向响应；回封后恢复则可计入正向响应。这样能降低把纯跟风最高板、无带动一字板或偶然热榜股直接认作龙头的概率。

“带动”仍只是30–60秒免费轮询形成的时间先后代理，不是逐笔因果证明：软件用第一段相邻快照识别封板/回封/炸板事件，只用事件后的下一张快照评价响应，避免把候选自身新增的1家涨停算作跟随。它仍无法可靠区分消息同时驱动、指数共振和股票主动带动。盘后首次使用只有静态候选，必须等下一个交易日持续运行并积累真实事件后才可能出现“已确认”。

### 首板身位与形态

身位分为两套口径：连板数决定“事件身位”，历史日线决定“价格身位”。连板股不会因为前几日涨幅较低而降级；首板股则必须有历史证据才能标为低位补涨。软件每日缓存强度前5行业相关封板股、炸板股、核心候选和大市值代表股的前复权日线，同时抓取对应行业指数日线。个股日线同时请求腾讯和东方财富并按交易日取中位数，行业指数当前使用东方财富口径；行业指数临时失败但至少3只大市值代表股有历史时，降级使用按总市值加权的样本涨幅，并在卡片标明，不把估算伪装成指数实值。

- 封板前5/10日涨幅：使用上一完成交易日收盘计算，避免把今天的涨停反过来当成“此前已大涨”。
- 封板前5日行业超额：个股封板前5日涨幅 − 行业指数同期涨幅，用来区分板块内滞涨与已领先。
- 当前3/5/10日涨幅和距20日高点：描述本轮总体价格位置，不单独作为看多分数。
- 近10日估算涨停次数、距上次估算涨停天数：按不同市场通常涨停幅度从前复权收盘变化估算，不替代交易所逐日涨停状态。
- 封板时间、封单/流通市值和当日成交：用于确认今天的强度，不会把单纯低位但封板弱的股票自动标成高可信补涨。

透明分类口径：首板且封板前涨幅温和、行业超额不高、近10日无估算涨停并获得当日强度确认，归入“低位补涨”；近2–6个交易日出现过估算涨停、断板后当天重新封板，归入“高位反包”；封板前5日≥8%或10日≥15%且接近20日高点，归入“趋势加速”；证据处于中间区域则为“中位跟随”。阈值是可解释的观察规则，尚未经过收益回测。日线少于所需长度时统一显示“历史不足待核验”，不猜测分类。

### 情绪分数（透明规则，未做预测回测）

设 N 为有效 A 股样本数，U/D 为上涨/下跌数，M 为样本涨跌幅中位数（以百分点计），S/W 为涨幅≥3%/跌幅≥3%的家数：

```text
score = 50 + 30 × (U-D)/N + 15 × clip(M/2, -1, 1) + 5 × (S-W)/N
```

评分范围 0–100。所选窗口内下降至少 5 分：低于45为退潮，65以上为高位分歧，其余转弱；上升至少5分：低于50为低位修复，否则升温；变化较小时，≤25为低迷观察，≥75为亢奋观察，中间为震荡。它不是上涨概率，不是买卖指令。

相对全市场 = 行业涨跌幅 − 有效样本等权平均涨跌幅。它不是沪深300超额收益。上涨占比 = 行业上涨家数 /（上涨+下跌家数），不包含平盘。成交额占比只在完整的31个一级行业内计算，不是资金净流入。

## 提醒与设置

默认采集间隔60秒，可选30/60/120/300秒；每轮完整分页需额外耗时，失败还会退避，不能承诺固定刷新频率。手动刷新限频20秒。默认判断窗口5分钟、连续确认3次、轮动排名变化阈值5名，可在面板修改，无需停止自选股监控。

轮动走强必须同时满足：窗口排名上升达到阈值、相对强度增加≥0.5个百分点、上涨占比≥55%；走弱为对应下降且上涨占比≤45%。情绪阶段变化和轮动条件均连续确认后记录。同类提醒冷却10分钟。提醒记录在本页显示，查看页面时新提醒会轻提示，当前不接入悬浮窗或额外系统推送。

第一次启动至少积累所选窗口长度的连续有效数据，随后才可能完成连续确认。15/30分钟名次变化各自需要相应历史。初始快照、旧时间戳、数据缺失、跨日、午休、竞价前段不产生变化提醒。暂停后重新打开可查历史，但不会把历史提醒重新弹出。多设备保存设置使用版本检查，发生冲突时保留当前草稿，不静默覆盖。

## 数据来源与降级

1. 东方财富全市场行情列表：固定代码排序，每页100条，并发4页，失败换网关补页，检查总数、重复项和完整性。多个网关属于**同一供应商**，不是独立源一致性验证。
2. 腾讯备用行情：只有曾获得完整市场名单才启用，按批采集。市场名单最多保留7天用于降级展示；非当日名单不产生信号，可能缺少新上市股票。不会把失败返回当成平盘或跌停。
3. 东方财富行业行情：接口目前混有多个层级，严格筛选31个一级行业；名称/口径变化或缺失时停止相应轮动信号。不会自动混入二、三级行业或概念板块。
4. 东方财富涨停板专题：核对返回日期与总数。空数据/失败显示“—”；只有服务明确返回0且列表为空才显示0。专题口径可能不含ST、科创板及部分新股，不宣称覆盖全部A股；股池只提供日期，没有可验证的逐笔更新时间，仅作辅助，**不计入评分、不单独触发提醒**。
5. 身位历史日线：个股同时请求腾讯与东方财富前复权日线并显示“双源”覆盖；行业指数日线使用东方财富。缓存按交易日复用，避免每分钟重复请求。最多为120只相关候选补抓历史，超出时页面明确披露未覆盖数。

盘中有效行情时间不能超过180秒；新鲜行情比例至少95%，必须有完整列表和足够的同日样本（全市场至少3000、一级行业31）。过期、无日期、无有效价格的项目被剔除，页面显示原始覆盖及有效样本数。以上是保守质量门槛，不是行情延迟保证。节假日沿用原程序配置；未配置节假日时也会通过日期/新鲜度拦截旧行情信号。

公共行情固定域名直连，不携带用户密钥、成本价或个人自选配置。若网络必须使用代理，当前这个新模块的直连可能不可用；不会修改系统代理。接口限制、授权条款、稳定性以供应商为准。

接口协议参考：[AKShare全市场行情适配](https://github.com/akfamily/akshare/blob/main/akshare/stock_feature/stock_hist_em.py)、[行业适配](https://github.com/akfamily/akshare/blob/main/akshare/stock/stock_board_industry_em.py)、[涨跌停专题适配](https://github.com/akfamily/akshare/blob/main/akshare/stock_feature/stock_ztb_em.py)。本项目直接使用 requests，不新增 AKShare/pandas 依赖。

## 保存与限制

独立文件位于 `data/market-monitor.db`（快照、日内轨迹、提醒，滚动保留30天）、`data/market-monitor-settings.json`（设置）、`data/market-universe.json`（公开股票名单缓存）、`data/market-position-history.json`（公开日线身位缓存）。这些文件继续被 Git 排除，不上传个人运行数据。默认不持久化“已开启”状态。

这是日内规则监控，不是完整预测模型：尚不包括长期情绪分位数、连板晋级率、昨日涨停隔日溢价、历史成分股回溯或交易收益回测。身位分类使用当前行业成分归属和最多25个交易日的公开日线，存在行业调整、复权差异及专题股池覆盖偏差。免费网页接口不等于交易所授权实时行情，不能保证不漏报或不误报。短线决策仍需结合交易风险自行判断。

## 接口

沿用本地 Host/Origin 校验和远程 Tailscale 身份授权，无公网新端口：

```text
GET  /api/market-monitor                   状态、快照、轨迹、提醒与设置
POST /api/market-monitor/start             开始连续监控
POST /api/market-monitor/stop              暂停；在途采集结束后停止
POST /api/market-monitor/refresh           异步单次采集（限频）
PUT  /api/market-monitor/settings          保存设置，必须带当前 _revision
```
